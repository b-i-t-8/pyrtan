pyrtan

Open-source automation built on decision trees you can read. Ask it something and it answers like an assistant, but there is no AI model inside.

Why trees instead of a model

An AI model can handle questions nobody planned for. Pyrtan can't, and it tells you so. In return, every answer is repeatable and free, works offline, only reaches the sites you allow, and shows exactly how it was reached.

Trees

A tree is one TOML file: the questions it answers, the sites it may reach, and how it decides. No code to write.

Swarm

Services run trees. A hub connects them and shows which ones are up. Run one process or many; nothing else changes.

Gaps

When a tree meets a case it doesn't cover, Pyrtan writes it down instead of guessing. That list tells you what to add next.

Catalog

Trees other people wrote. pyrtan pull NAME downloads one and checks it before saving it.

Install

uv tool install git+https://github.com/b-i-t-8/pyrtan     # or: pip install git+https://github.com/b-i-t-8/pyrtan
pyrtan search weather
pyrtan pull weather --dir trees
pyrtan serve trees --port 8701                            # then open http://127.0.0.1:8701/

Needs Python 3.12 or later and nothing else. Runs on a laptop, a NAS or a container. See the deployment notes.

The console

Every hub has a web console at /. You can also use it here at pyrtan.com/console: start your hub with --token and --cors https://pyrtan.com, then connect to it from anywhere. Your browser talks to your hub directly; nothing passes through this site.

The directory

Hubs find each other without a central server. Start a hub with --listed and it tells the hubs it is connected to, which pass the word on. Below are the hubs in the default network, the one pyrtan join uses. You can also start a private network of your own; its hubs don't show up here.

This list comes live from the hubs on the hub list. If none of them answer, you see the hourly snapshot instead. To use a hub, connect to it from your own.

StatusHubTrees
Asking the hubs…
pyrtan hub --federate --advertise https://your-hub --listed --token …   # your hub, behind a tunnel or TLS
pyrtan join --at https://your-hub --token …                             # join the default network
pyrtan network new home --at https://your-hub --token …                 # or start your own; prints an invite
pyrtan directory                                                        # list the hubs you know of

To add your hub to the hub list, open a pull request adding its URL to site/rendezvous/hubs.json. It doesn't need to be online all the time.

Hosting

Self-hosting comes first. A hosted version is planned: the same open-source hub, run for you, with secrets, scheduled runs and alerts. It will use the same API, so you can move between the two at any time.
